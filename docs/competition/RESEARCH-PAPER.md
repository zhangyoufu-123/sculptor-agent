# SCULPTOR：以"作者建模"为中心的深度协作写作 Agent

**——风格差异弥补、个人知识组织与创作流程设计**

*中文研究论文（投稿/参赛版）· v0.23 · 2026-08-10*

---

## 摘要

大语言模型（LLM）已具备通用文本生成能力，但用于个人写作时普遍存在"千人一面、AI 腔明显"的问题。
本文提出一个核心论断：**通用写作的下限由模型能力决定，而上限由系统对"作者"的理解决定**。
据此设计并实现了 SCULPTOR——一个嵌入 Agent 环境（Codex / Claude Code / OpenCode）的深度协作写作系统。

SCULPTOR 的理论基础是把风格定义为**个体表达对"完美表达"的结构化偏离**，并以四层互补表征近似该偏离：
L1 连续向量（作者语料相对通用基线的方向差，EMA 增量更新）、L2 动态维度（14+7 维语言/结构轴
及其派生的意象、偏好、素材子维）、L3 困惑度签名（人类文本的 surprisal 特征）、
L4 偏好对（`原文, 改后, 意图` 编辑行为信号）。
同时区分"人想写的风格"（write-style）与"人想听的风格"（read-style）两个分布。

在知识侧，SCULPTOR 以"读过的书是写作的土壤"为原则构建个人知识库（PKB），
采用归纳式确认采集、提问去重、检索轮换注入三条纪律，使知识、作品、检索来源三类数据互通。
在流程侧，系统显式化 Flower & Hayes 的"规划—转译—复阅"认知写作模型，
形成"澄清→大纲→写作→复阅→红队→读者群像→交付"七阶段闭环；
并针对文体提供学术论证链、角色预演、文章圣经、情绪曲线等机制。

系统离线全链路自动化测试 337 项断言，覆盖从澄清到交付的全部环节；
真实任务的反 AI 审计表明，系统能检出并自动修复重复比喻、句式复用与套话，
成稿人类化指标（句长标准差 14.4、段落变异系数 0.45、句首去重率 81%、二元 TTR 0.78）处于真人写作区间。
本文同时给出对照实验、消融实验与用户盲评的完整方案，作为后续实证研究的基础。

**关键词**：写作 Agent；风格提取；个人知识库；检索增强生成；多 Agent 协作；认知写作模型

## 1 引言

### 1.1 问题背景

以 ChatGPT、DeepSeek、Claude 为代表的 LLM 让"机器能写"成为常态，但个人用户很快发现一个
普遍现象：让 AI 代写的文章"像模像样，却一眼假"——结构工整、辞藻平滑、情感千篇一律。
我们把这种现象称为 **AI 腔**：它来自生成分布对"规范、平滑、无风险"文本的偏好。

现有工具试图通过提示词工程（"模仿余华""写得更像人"）缓解，但效果有限，
因为提示词无法携带足够细粒度的作者信息；而微调需要大量样本且成本高昂。
更根本的问题是：**系统从未建立"作者是谁"的模型**。

### 1.2 核心观察与主张

通过大量写作协作实践，我们总结出四个现象，并认为它们指向同一根因：

1. **风格错配**：同一作者写散文时是文学性的，写议论文时是理性的——系统若用散文指纹生成
   议论文，必然失真，说明风格与文体强耦合，需要按文体采集；
2. **素材伪门槛**：用户澄清时已提供的案例与数据未被结构化传递到写作阶段，导致重复追问或
   空转，说明信息流缺乏"作者记忆"的中转站；
3. **交互死板**：模板化追问无法从用户原话生长，用户说"没有更多了"仍被反复询问，
   说明澄清策略需要状态感知与意愿识别；
4. **数据孤岛**：读过的书、写过的文、检索到的资料彼此隔离，无法共同支撑一篇文章，
   说明写作系统缺乏统一的知识组织。

由此提出本文主张：**写作系统应以"作者建模"为中心**——持续维护一个关于作者的
风格模型、知识模型与意图模型，并让创作流程围绕它们运转。

### 1.3 主要贡献

本文的贡献包括：

- **理论层面**：形式化"风格 = 个体表达对完美表达的结构化偏离"的差异弥补模型，
  提出四层互补的风格表征架构与"双风格"（write/read）分离原则；
- **系统层面**：实现完整的七阶段创作闭环，并将个人知识库、实时检索回灌、
  文体专属机制（论证链/角色预演/文章圣经）整合进同一状态机；
- **协作层面**：定义"写作生态位内主导、生态位外让位"的多 Agent 协作协议，
  解决"AI 抢话"与"AI 边缘化"的两难；
- **工程层面**：零依赖 Node CLI + 确定性兜底，LLM 不可用时流程降级不崩溃；
  337 项离线断言与引擎同步 CI 保证可复现、可维护。

## 2 相关工作

### 2.1 通用 AI 写作与 AI 腔检测

通用 LLM 通过大规模人类语料预训练获得"平均化"的写作风格，其生成文本在统计上偏向
高频连接词、均衡句式与安全表达。已有工作从语言统计学角度刻画 AI 腔：
重复比喻、句式模板化、句长方差偏小、词汇多样性偏低（TTR 下降）。
SCULPTOR 将这类指标内建为"红队审计"的确定性检查项，并在生成端施加硬约束
（黑名单词、比喻唯一性、句式去重），形成"生成约束 + 事后审计"双保险。

### 2.2 风格迁移与模仿

风格迁移（style transfer）研究将文本改写为另一风格而不改变内容，主流方法包括
对抗训练、预训练模型微调与风格嵌入。CPM/GLM 等中文大模型亦提供"模仿作家"能力。
这些方法以"名人风格"为模仿目标，无法处理"普通人的个人风格"，且通常需要成对数据或
大量目标风格样本。SCULPTOR 的差异在于：不模仿任何固定对象，而是从作者本人的
历史语料、编辑行为与知识背景中持续学习其**个人**偏离方向。

### 2.3 学术写作 Agent

AgenTex 采用多 Agent 架构，按 IMRaD 结构生成论文大纲并以苏格拉底式提问引导研究者澄清论点；
BuildIntroArgumentChain 将引言规划为"已知问题→缺口→张力→洞见→方法→证据承诺"的论证链。
SCULPTOR 吸收论证链思想并扩展到全文：澄清阶段可补问研究缺口/方法/局限，
大纲与逐节写作按论证链位置推进，交付前做逐节论证完备性扫描
（claim/evidence/warrant，结论节另查 limitation）。

### 2.4 角色与叙事模拟

MATE 提出确定性情感中间件，为 LLM 伴侣提供持久情绪与涌现性格；
DiriGent 用"理想世界与感知实际世界的张力"驱动叙事 Agent 的可信行为。
SCULPTOR 的角色预演采用同一张力模型：为每个角色维护背景、愿望、恐惧、秘密、
说话方式与情绪记忆的持久档案，写作前让 LLM 以角色第一人称预测其情绪、言语与行为，
并将预测注入正文写作，使故事"从人物身上长出来"。

### 2.5 记忆与知识管理

MemGPT 提出分层记忆与自我编辑，让 LLM 在长对话中维持核心记忆；
Alexandria 强调知识条目的来源可引、人可读；基于 LLM 的书籍推荐利用用户阅读历史做语义匹配。
SCULPTOR 的个人知识库（PKB）综合三者：条目以人类可编辑的 Markdown 存储、
带来源与置信度、按主题 BM25 检索注入，并实现"同一本书只问一次"的提问去重。

### 2.6 写作认知模型

Flower & Hayes 的认知写作理论将写作过程分为**规划（planning）、转译（translating）、
复阅（reviewing）**三阶段，且强调复阅贯穿全程。绝大多数 AI 写作系统只实现"转译"
（一次生成成稿），缺少显式的规划与复阅。SCULPTOR 将规划显式化为澄清与大纲，
将复阅显式化为初稿后的"复阅—修订"阶段（自动检查偏题、衔接、素材用足、字数注水，
对 P0 问题自动修订一轮），使用户的编辑行为成为最强的风格反馈信号。

## 3 理论框架

### 3.1 风格差异弥补模型

设文本空间 $\mathcal{T}$ 上的通用"完美表达"分布为 $P_{\mathrm{base}}$（平滑、规范、无风险），
作者 $a$ 的个体表达分布为 $P_a$。定义作者风格为其对完美表达的**结构化偏离**：

$$\mathrm{Style}(a) = \phi\big( D(P_a \| P_{\mathrm{base}}) \big)$$

其中 $D(\cdot\|\cdot)$ 为分布距离（如 KL 散度或 Wasserstein 距离），$\phi$ 将其投影到
可解释的特征空间。由于 $P_a$ 不可观测，SCULPTOR 用四层表征从不同证据源近似该偏离：

| 层 | 名称 | 证据源 | 表征 |
| --- | --- | --- | --- |
| L1 | 连续向量 | 作者语料 vs 通用基线 | 稀疏/稠密嵌入的方向差，EMA 增量更新 |
| L2 | 动态维度 | 风格档案 + 素材/意象/修改意图 | 14+7 维语言/结构轴 + 派生子维 |
| L3 | 困惑度签名 | 作者文本统计 | surprisal（少见二元组占比、低重复率、句长方差） |
| L4 | 偏好对 | 用户编辑行为 | $(原文, 改后, 意图)$ 对比信号 |

四层互补的理由：L1 捕捉**分布层**的整体方向差；L2 提供**语义层**的可解释维度；
L3 刻画**统计层**的人类不确定性（人类文本的 surprisal 显著高于 AI 平滑文本）；
L4 是最强证据——用户主动修改直接暴露其偏好，且与意图（"太文艺了""更克制"）绑定。

### 3.2 双风格分离原则

实践表明"人想写的"与"人想听的"是两种不同分布：作者希望自己表达为 A（如克制内敛），
但期望读者感受到 B（如温暖可亲）。SCULPTOR 分开维护 write-style（语言层 14 维）
与 read-style（结构层 7 维：节奏、信息密度、情绪曲线、开头/结尾口味、摩擦容忍度、格式偏好），
分开采集、分开注入，避免用单一风格向量约束两种需求。

### 3.3 知识即土壤

我们认为作者的联想与理论均来自"读过什么 + 经历什么"。PKB 遵循三条纪律：

1. **归纳式确认**：用户提到《书名》时，AI 只提议"如果它读过，告诉我一声"，同意才记录——
   不硬塞，尊重"没读过但只是提到"的边界；
2. **提问去重**：同一作品/话题只问一次（`asked.jsonl`），拒绝也算已问；
3. **轮换注入**：BM25 检索命中后，未用条目加分、已用条目按次数递减（封顶 -0.45），
   避免同一本书被反复引用而让读者起疑。

知识、作品、检索来源三类数据在统一素材层互通：网络检索回灌的书目自动入知识库
（标注来源与置信度），荐书联想在思想库未命中时自动联网检索。

### 3.4 认知写作流程

将 Flower & Hayes 模型实例化为状态机：**规划** = 澄清（需求+风格+知识采集）与大纲
（文体蓝图 + 论证链/故事骨架）；**转译** = 逐节写作（注入风格侧写与统一素材）；
**复阅** = 初稿全文复查（P0 自动修订一轮）+ 红队反 AI 审计 + 读者群像感性反馈。
用户在任何阶段的编辑行为都回写为风格证据（L4 偏好对与风格脉搏）。

### 3.5 生态位协作

多 Agent 环境的根本矛盾是"AI 抢话"与"AI 边缘化"的两难。SCULPTOR 的解法是**生态位原则**：
在写作生态位内（长文/风格/结构/定点修改），系统主导决策（问什么、何时写、要什么数据）；
在生态位外（编程、答疑、翻译、总结），完全让位。协作通过请求-回灌协议实现：
系统需要数据时写入 `requests.jsonl`，宿主或学术/数据分析 Agent 检索后回灌，
系统自动用新数据重写缺口节。

## 4 系统设计

### 4.1 总体架构

```
宿主对话（Codex / Claude Code / OpenCode）
  │  probe 生态位判定（只在写作任务触发）
  ▼
Skill 包（SKILL.md 协议 + 内嵌引擎快照）
  ▼
引擎状态机（.sculptor/protocol/state.json）
  ├─ 风格引擎：双档案 · 四层向量 · 侧写 persona · 风格脉搏
  ├─ 知识引擎：PKB · 个人写作库 · 思想/资产库 · RAG 实时取数
  ├─ 创作流程：澄清→大纲→写作→复阅→红队→群像→交付
  └─ 协作协议：requests.jsonl 检索队列 · rag_ingest 回灌 · data_needs
```

引擎为零依赖 Node CLI（`agent/` 为单一事实源），Skill 内嵌引擎由同步脚本生成，
CI 校验二者不漂移。所有 LLM 调用可失败降级：澄清退回单问题阶梯、角色预演退回规则预测、
读者群像退回确定性兜底、检索走宿主代检，流程永不中断。

### 4.2 风格引擎

- **信号采集**：用户每一句话（含修改理由）都作为风格信号；方向规则（"更克制/更豪迈/更口语"
  等 9 类）确定性落档，识别到方向变化时自动触发全文重写。
- **底稿提取**：用户粘贴 ≥80 字的旧稿自动落盘并做 14 维 LLM 提取。
- **四层向量**：见 3.1，`refreshStyleVector` 在澄清每轮、大纲、每节写作后增量更新。
- **人物风格肖像**：从知识库、旧作、修改记录侧写叙述视角/词汇/句式/情感/价值观/套路与盲区/
  引用习惯/与读者共鸣方式，注入写作并映射回向量；带过拟合护栏（"习惯而非牢笼"）。
- **风格脉搏**：澄清、大纲、每节写作后即时评估（不做交付前一次性大考），
  每节脉搏建议自动带入下一节。

### 4.3 知识引擎

- **PKB**：见 3.3；条目存储为人类可编辑 Markdown（JSON 头 + 笔记，0600），支持跨工作区
  export/import。
- **统一素材层**：大纲与写作注入 = 知识库 + 检索回灌来源 + 内置写作资产
  （文法连接/诗词典故/论证骨架，确定性防幻觉），限量轮换、动态预算裁剪。
- **实时取数**：澄清（clarify-data）、大纲缺素材节（outline-gap）、写作"素材不足"标注
  （write-gap）三处自动排队检索；回灌后若数据晚于写作，状态机自动重写缺口节
  （最多 2 轮数据补给）。

### 4.4 创作流程

七阶段状态机：

1. **澄清**：一次一问、从用户原话生长；问题生成有确定性硬校验（单问句、禁止多问）；
   连续低意愿（"没有更多了"）即终止，不把"继续"误判为低意愿。
2. **大纲**：文体驱动蓝图（论文问论点×N、公文问事项/主送/依据、小说问伏笔/反转）；
   素材门槛未过不准生成；生成后自动评审微调，用户确认后才进入写作。
3. **写作**：逐节生成，注入双风格档案 + 风格侧写 + 统一素材 + 角色预演；
   字数不足自动扩写，仍不足则标注"素材不足"并触发检索。
4. **复阅**：初稿全文复查（偏题/衔接/素材用足/字数），P0 自动修订一轮。
5. **红队**：反 AI 审计（黑名单、重复比喻、句式复用、人类化统计指标）+ 自动修订，最多 3 轮。
6. **读者群像**：8 位"第一读者"（老教师/挑剔编辑/中学生/评论家/家长/历史爱好者/随性读者/
   年轻作者）第一次阅读的心理反馈，分歧最大的 3 位交锋收敛出共识/争议/优先级。
7. **交付**：归档个人写作库并蒸馏个人 skill、沉淀文章圣经、导出 docx、生成参考文献草稿。

### 4.5 文体专属机制

- **学术论证链**：known→gap→tension→insight→method→evidence→limitation，
  大纲与逐节按链推进；完备性扫描逐节检查 claim/evidence/warrant。
- **角色预演**：持久角色档案 + 理想-现实张力，LLM 第一人称预测情绪/言语/行为并注入正文；
  情绪记忆回写档案保证整篇连续。
- **文章圣经**：交付时沉淀世界观/角色/时间线/伏笔/文风约定，系列文续写自动注入。
- **情绪曲线**：按节量化强度与主导情绪（平静/喜悦/哀伤/愤怒/张力），供节奏检查。
- **反 AI 硬规则**：黑名单禁用词、比喻唯一性、句式去重、段落长短错落、
  连续成稿（禁小标题与舞台提示）。

## 5 评估

### 5.1 自动化测试体系

337 项离线断言覆盖：澄清→大纲→写作→复阅→红队→群像→交付全链路、四层风格向量、
知识库收录/去重/轮换、实时取数排队/回灌/自动重写、文章圣经、角色预演、MCP 工具、
凭证安全与密钥扫描。所有 LLM 调用使用离线 mock，测试确定性、可复现，
适合作为比赛要求的"研究过程可验证"证据。

### 5.2 真实任务反 AI 审计与人类化指标

在真实写作任务（《百年历久，北大红楼》游记）中，系统按完整流程产出全文，随后红队审计检出
并自动修复两处 AI 痕迹：跨节重复比喻（"像有人跟在后面"→"像旧朝宫人踏过回廊"）与
"不是…而是…"句式复用。终审黑名单 0、硬失败 0。

成稿人类化指标如下（均在真人写作参考区间内）：

| 指标 | 数值 | 含义 |
| --- | --- | --- |
| 句长标准差 | 14.4 | 长短句交错，节奏不平均 |
| 段落变异系数 | 0.45 | 段落长短错落 |
| 句首去重率 | 81% | 句首不重复 |
| 词汇二元 TTR | 0.78 | 用词多样性高 |

### 5.3 实验设计（对照 / 消融 / 用户盲评）

为满足科研型比赛对"因果证据"的要求，提出如下实验方案（作为后续实证工作的基础）：

**实验一：风格保真度对照实验。** 让 N≥20 名受试者各自提供 300 字以上的同文体旧稿，
分别用通用 LLM（对照组）与 SCULPTOR（实验组）为每位受试者生成同题目文章。
评估指标：(a) 客观——人类化统计指标（句长标准差、TTR、句首去重率）与 L3 困惑度签名的组间差异；
(b) 主观——组织 3 名以上独立盲评人，对"哪篇更像该作者本人"进行成对盲评（A/B 选择）。
预期：实验组在"更像本人"选择率上显著高于对照组（>60%，χ² 检验 p<0.05）。

**实验二：消融实验。** 从 SCULPTOR 中依次移除 (a) L4 偏好对、(b) 个人知识库注入、
(c) 人物风格肖像、(d) 复阅-修订阶段，比较各条件下生成文本在盲评与人类化指标上的下降幅度，
以量化每个模块的边际贡献。

**实验三：用户体验实验。** 让受试者完成一次完整写作任务（澄清→大纲→写作→修改），
记录任务完成时间、澄清轮数、修改次数与主观评分（理解度、掌控感、成品满意度），
与不使用系统直接与 LLM 对话的对照组比较。

以上实验数据采集完成后，将补充"结果与讨论"章节并更新指标表。

## 6 局限与伦理

### 6.1 局限

- **跨会话知识统一**：PKB 已支持 export/import，但尚未实现跨工作区的自动同步；
- **双人合写**：两份风格侧写的融合尚未实现；
- **联网内容质量**：网络回灌来源已标注"待核实"，但缺少自动置信度评估；
- **成本**：角色预演每节增加一次 LLM 调用，需按文体与篇幅进一步限流；
- **评估样本**：第 5.2 节的指标来自单次真实任务，需要实验一/二的规模化验证。

### 6.2 伦理

系统采集并存储用户的写作样本、阅读记录与编辑行为，遵循以下原则：
(1) 数据仅存于本地工作区，权限 0600，不主动上传；
(2) 知识库导出时明确提示隐私风险；
(3) 网络来源一律标注"待核实"，防止未经验证的信息进入个人知识体系；
(4) 系统鼓励作者保持主体性——侧写带过拟合护栏，修改意见永远优先于模型输出。

## 7 结论

SCULPTOR 将"作者建模"作为写作系统的中心：用四层风格表征近似"个体对完美表达的结构化偏离"，
用个人知识库承载"读过什么决定怎么写"，用七阶段状态机实例化认知写作模型，
并用生态位协作协议解决多 Agent 环境的定位问题。337 项自动化断言与真实任务审计表明，
系统在稳定性、可复现性与人类化指标上达到可交付水平；本文给出的实验设计为后续
规模化实证提供了清晰路径。
