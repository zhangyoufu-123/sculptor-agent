# SCULPTOR 参赛过程档案

**——从"AI 腔治不好"的困惑，到"作者建模"写作系统的完整推进记录**

> 项目：SCULPTOR：以"作者建模"为中心的深度协作写作 Agent
> 版本历程：v0.5 → v0.53（2026-08 全周期）
> 用途：科技比赛过程材料（选题、推进、复盘、实验、成果）

---

## 1. 项目缘起与选题

### 1.1 从哪里开始：一次真实的"难受"

项目的起点不是一篇论文，而是一次写作体验的困惑：让 AI 代写文章，"像模像样，却一眼假"——
结构工整、辞藻平滑、情感千篇一律，被称作 **AI 腔**。最初我们以为换个更大的模型、写个更长的
提示词就能解决，但反复尝试后发现：**问题不在模型，在于它不认识你**。它不知道你读过什么、
在意什么、句子习惯怎么断、情绪习惯怎么收；它写的是"一篇好文章"，而不是"你写的文章"。

在真实写作协作中，我们进一步观察到四个普遍现象：

1. **风格错配**：同一个用户写散文时是文学性的，写议论文时是理性的——系统若用散文指纹生成
   议论文必然失真；
2. **素材伪门槛**：澄清阶段用户明明说过案例与数据，写作阶段却"没收到"，导致重复追问与空转；
3. **交互死板**：模板化追问无法从用户原话生长，用户说"没有更多了"仍被反复询问；
4. **数据孤岛**：读过的书、写过的文、检索到的资料彼此隔离，无法共同支撑一篇文章。

这四个现象指向同一个根因：**系统从未建立"作者是谁"的模型**。选题由此确定——
构建一个以"作者建模"为中心的深度协作写作 Agent。

### 1.2 一句话主张

> **通用写作的下限由模型能力决定，上限由系统对"作者"的理解决定。**

在人文科学时代，机器越是会写，人越需要守住"自己的表达"——本项目把自己定位为
**帮助产品**：写作者不必迁就机器，让机器学习成为他。

## 3. 关键"问题 → 根因 → 解决"复盘（比赛最看重的部分）

### 案例 1：长文分节结构损坏（v0.42.1）

- **现象**：12000 字小说端到端测试中，成稿的节标题被粘进上一节正文末尾，节奏曲线少了一节。
- **根因**：导演逐节写作时 `split(/\n(?=## )/)` 会吃掉 `##` 前的换行，直接 join 导致节粘连；
  此前测试只验字数不验结构。
- **解决**：写回前补齐换行（`joinParts` 安全网），并新增"节标题独立成行/无粘连"回归断言。
- **方法论收获**：测试必须验证"结构不变量"，不只是"产出非空"。

### 案例 2：真实 LLM 下大纲 JSON 被截断（v0.49）

- **现象**：7500 字论文生成大纲时，推理模型把 token 花在思考上，大纲 JSON 被 3000 token 截断，
  导演把原始 JSON 当问题丢回给用户。
- **根因**：`maxTokens` 预算不足 + 解析失败无重试。
- **解决**：预算 3000→6000、temperature 降为 0.5、解析失败带"补全提示"自动重试一次。
- **方法论收获**：mock 测试永远抓不到真实模型的 token 行为，必须跑真实 LLM 全流程。

### 案例 3：真实 LLM 澄清不主动收尾（v0.49）

- **现象**：蓝图字段全部确认后，真实模型仍继续追问（问得挺好，但不收尾）。
- **根因**：LLM 不遵守提示词里的 stop 规则；确定性护栏只覆盖"低意愿"，不覆盖"无缺口仍追问"。
- **解决**：导演侧"确定性收尾护栏"——无缺口仍被追问 ≥2 轮即强制放行进大纲；
  放在导演层，interview 等独立流程的完成语义不受影响。

### 案例 4：提问死板 → 思想脉络 → 提问主次 → 去硬编码（v0.43–0.44.1）

- **现象**：澄清只能搭结构、问不出深层思考；用户引《乡土中国》推出"烂梗根源"，
  AI 却把它当素材记下继续问大纲。
- **推进**：v0.43 新增思想脉络（主张-前提-推理-理论来源，LLM 做一步概括再请确认）；
  v0.44 提问主次重排（先思想、后信息、最后规划）；v0.44.1 把排序映射删除，
  蓝图状态清单化 + RAG 知识背景注入，问什么由 LLM 自主判断。
- **方法论收获**：规则若由代码钦定顺序，再合理也是"硬编码"；要让 LLM 有判断空间，
  代码只做防死循环的安全网。

### 案例 5：AI 假思考（v0.52–v0.53）——本项目最重要的一次复盘

- **现象**：《语言匮乏》类文章统计指标全达标（黑名单 0、句长σ 17.1、TTR 0.59），
  读者却"难受"——它是"正确语言的堆积"，讲述失语的声音本身也是失语的。
- **根因（文本细读）**：声音分裂（角色嘴和作者手分离）、过渡公式化、修辞空转、
  引用挂靠（检索式写作）、翻译体、金句收尾空转——六层问题全在"姿态层"，
  统计指标抓不住。
- **推进**：v0.52 提示词前置禁令（反金句收束/允许冗余与模糊/不替人物开口/反过度释义）
  + 确定性姿态层检测；v0.53 把硬编码正则降级为兜底，主路径升级为
  **LLM 六层细读 + RAG 作者对照**（诊断前检索 persona/个人写作 skill/知识库作声音参照）。
- **方法论收获**：AI 味有统计层和姿态层两层；姿态层需要"先懂作者、再判断像不像作者"，
  这本身就是作者建模理论的自洽证明。

### 案例 6：Web 端一系列体验问题（v0.27–v0.48.1）

- 右侧面板遮挡对话 → 改伴随式工作台；布局拥挤 → 分栏重排；
- 实时大纲不实时 → 大纲贯穿全程、完成即进入写作；点击无反应 → 统一视图路由与接线检查；
- 前端"所有 `$()` 引用必须有对应 id"静态检查进 CI——一次接线回归被测试拦住；
- 接口自检（v0.48.1）：30 个前端调用零断链、29 个调用点 HTTP 方法全一致，清理 1 处死元素。

## 4. 实验与数据汇总

### 4.1 自动化测试规模（可复现）

- agent 端 **19 套** + web 端 **7 套** QA 全绿；
- 覆盖：一次一问与低意愿逃生、实时大纲、字数达标（85% 阈值 + 扩写两轮）、
  红队 8 文体 × 6 对抗输入、十种用户说法、风格差异对照、12000 字长文端到端、
  翻译/回译校验、假思考六层细读、全格式导出、前端接线静态检查。

### 4.2 反 AI 审计与人类化指标

- 真实任务：跨节重复比喻被检出并改为不同意象，终审黑名单 0、硬失败 0；
- 成稿人类化指标处于真人区间：句长标准差 14.4、段落变异系数 0.45、
  句首去重率 81%、词汇二元 TTR 0.78；
- 诚实短板（写入论文）：统计层抓不住姿态层假思考，v0.53 以 LLM 六层细读补上。

### 4.3 风格向量对比（数学推导见 STYLE-MATH.md，三图见 style-vectors-*.png）

- 8 维归一化风格向量 + 欧氏距离：SCULPTOR↔史铁生 1.11、↔费孝通 1.54、
  ↔ChatGPT 1.46、↔DeepSeek 1.49、↔模板公文 1.98；两个通用模型彼此仅 0.65（AI 腔趋同）；
- 综合写作能力（加权评分）：SCULPTOR 87.4 vs ChatGPT/DeepSeek 38.6、模板 34.0；
- 同题三套风格对照：句长σ 3.7/8.3/5.0、字数 742/874/984、TTR 0.44/0.53/0.52——
  风格注入真实改变写法。

### 4.4 实验工具（评审可现场复现）

- `sculptor experiment metrics/collect/run/ablation/survey/blind/summarize`：
  语料采集、baseline vs 风格注入对照、消融、盲评问卷、二项检验汇总；

## 6. 研究感悟（真实复盘）

这次研究让我收获最大的不是"让 AI 更聪明"，而是**理解人**。AI 腔的本质是机器用平均值覆盖
个体；而 SCULPTOR 想做的，是让每个普通写作者在被 AI 包围的时代，仍然能说出"这是我的话、
我的想法、我的风格"。技术层面我经历了从理论到 19+7 套自动化测试全绿的全过程，也亲历了
"测试抓出真 bug"（长文分节粘连）与"真实 LLM 暴露 mock 覆盖不到的坑"（大纲截断、澄清不收尾）。
更深的一课来自《差生》和《语言匮乏》的对照：**写得好不好，统计指标说了不算，姿态说了算**——
这也是为什么我们最终把"作者建模"坚持到底。
