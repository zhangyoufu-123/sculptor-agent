# 问询系统升级文档 v1

> 缘起（用户原话）："根据这几次的对话升级问询的系统，根据我的主动说出的所有问询系统中本来不准备问的问题。这是升级的关键。"
> 日期：2026-08-12｜适用范围：Stylotrace 澄清（Phase 1）与思想脉络（v0.43）机制

## 一、诊断：当前问询系统的盲区

现行澄清协议（questioning.md）的核心假设是：**系统提问，用户回答，问题清单逐项填满**。它允许"打破顺序接住用户刚说的话"（v0.44），但本质上仍是"围绕系统的问题收集答案"。

这几次对话暴露了一个系统没准备好的事实：**用户最高价值的信息，恰恰不是系统问出来的，而是用户主动说出来的、系统本来不准备问的东西。** 这些信息一旦出现，就应当立即重排整个澄清流程，而不是被当作"背景素材"归档。

## 三、结论：系统缺的不是"更会问"，是"更会接"

用户主动说出系统没准备问的信息，其价值排序远高于系统问出来的答案，因为：

1. **它带着情绪入口**（触发点、感慨），是立意的胚胎；
2. **它带着私人坐标**（家庭、师承、代际），是"个人写作"不可替代的矿脉；
3. **它带着论证与红线**（推理线、台词、情节约束），是质量的硬边界；
4. **它带着参照系**（某作品/作者/媒介），同时泄露了叙述策略与风格取向。

现行系统把这些统统归入"素材"，等澄清收尾再提炼立意——**节奏错了**。种子应该在它出现的那一刻就被识别、回显、确认，并重排剩余澄清。

## 四、升级原则

1. **外溢优先**：用户主动说的信息 > 当前问题 > 清单顺序。检测到外溢，立即暂停原问题链。
2. **种子即立意**：外溢信息不叫"素材"，叫"种子"（seed）。种子出现即回显确认，不等蓝图阶段。
3. **参照系是入口不是背景**：用户提到任何作品/作者/媒介，必须追问一句"这个参照系里，哪一点击中了你"，并把它作为候选叙述策略注入。
4. **红线不可润色**：用户指定的台词、情节、格式约束，进入红线清单，大纲/写作/红队/重写全程校验。

## 五、机制改造

### 5.1 外溢分类器（每轮回复必经）

澄清每轮对用户回复自动分类，不只判断"答没答":

- `answered`：正常回答了当前问题 → 走原清单；
- `overflow-reference`：给出参照系（作品/作者/媒介）→ 触发"哪一点击中你"追问；
- `overflow-personal`：给出私人网络（家庭/师承/代际/口传）→ 触发"这条线怎么传到你"追问；
- `overflow-constraint`：给出红线/技法（台词、情节、修辞、格式）→ 立即写入红线清单与 styleDirections；
- `overflow-reasoning`：给出理论/推理线 → 按思想脉络协议复述＋顺推一层＋回显确认。

### 5.2 外溢深挖子流程（最多 2 问，然后回主线）

检测到外溢后：

1. 先一句话复述外溢内容，确认理解（"你的意思是……对吗"）；
2. 深挖一问（按类型触发模板，见第六节）；
3. 记入 `state.overflowLog`，标记该种子为"已确认"，回到清单剩余项。

### 5.3 素材两级制（unifiedBrief 改造）

素材库从单级改为两级：

- **fact-material（事实素材）**：检索回灌、数据、引文，按篇幅预算达标；
- **seed-material（种子）**：用户主动给出的立意/红线/技法/参照系/私人网络。

大纲门槛改为：**种子必须全部兑现，事实素材按预算达标**。当前"素材 ≥8 条"的预算没有区分两者，导致种子被稀释。

### 5.4 回显协议强化

用户主动给的种子必须**本轮内**回显确认（不是攒到蓝图阶段）。确认后立即写入：

- `coreThesis`（立意种子）
- `constraints`（红线清单，新字段）
- `styleDirections`（技法/参照系）
- `vault/overflow-log.jsonl`（升级信号，新文件）

### 5.5 升级信号流水（自进化闭环）

每次"用户主动说出系统没准备问的信息"，自动记一条：

```json
{
  "ts": "…",
  "task": "悼念朱镕基",
  "asked": "你最先浮起他的哪个画面/哪句话？",
  "userSaid": "小约翰可汗《硬核狠人》……死前的平静平凡与传奇人生的差别",
  "overflowType": "reference",
  "lesson": "悼念类写作，情绪入口比生平信息更重要；先问触发点，再问生平",
  "questionTemplateFix": "从『你记忆里第一个画面是什么』改为『你最先想到的是什么——一个画面、一句话、一个人、还是某个让你想起他的东西』"
}
```

每 5 个任务或每周，把 overflow-log 汇总成 `docs/questioning-upgrades.md`，反哺 questioning.md。**这就是"根据我主动说出的所有系统没准备问的问题"的机制化。**

## 六、问题模板改写示例

| 场景 | 原模板（收集答案） | 新模板（留出入口） |
| --- | --- | --- |
| 悼念/纪念类 | 你记忆里和他有关的第一个画面是什么？ | 你最先想到的是什么——一个画面、一句话、一个人，还是某个让你想起他的东西？ |
| 素材 | 你身边还有哪些具体场景可以写进去？ | 你脑子里有没有现成的线索：一部作品、一段家庭往事、一条推理线，哪怕它看起来和主题无关？ |
| 立场 | 你想突出他哪一面？ | 是什么让你现在想写这篇？先说那个触发点，我们再定怎么写。 |
| 论证 | 你打算怎么论证这个观点？ | 你心里有没有一条现成的推理线或一本书，可以顺着想？ |
| 约束 | 结尾有什么要求？ | 有没有哪句话、哪个情节、哪个词，是你定死了不许改的？ |

## 八、验证方法（下 3 个任务）

1. 记录每轮澄清中"用户主动说出系统没问的信息"的次数与类型（overflow-log）；
2. 检查每个种子是否在当轮被回显确认、并在成稿中兑现（红线 100%、技法 100%）；
3. 对比升级前后：用户需要重复/纠正的次数是否下降；立意确认是否提前。
