# Web 端人机交互规划（辅助手动写作 · 实时反馈 · 可视化）

> 版本：v0.45 规划 · 2026-08-11
> 目标：把 Stylotrace Web 从"聊天 + 表单"升级为"伴随式写作工作台"——作者亲手写，
> AI 在选区、节奏、思想上贴身反馈，全程可见、可改、可回滚。

---

## 1. 同行调研（2026-08）

| 产品 | 值得学的交互 | 我们的对应/差距 |
| --- | --- | --- |
| Sudowrite | **Selection Menu**：选中文字才出现 AI 动作（改写风格/Describe/Related Words）；改写结果进 History 卡片，可接受/重试；Write 功能读光标前后 1000 字给 3 个续写方向 | 已有选区点改（`point-edit`），缺**选区快捷动作组**与**结果卡片（Accept/换一个）** |
| NovelCrafter | 侧栏 + 主面板在 Plan/Write/Chat/Review 间切换；**Chat 与 Plan 分屏并排**，边聊边改大纲 | 已有三栏骨架（对话/大纲/上下文），缺"写作时 Chat 与手写区并排"的伴随感 |
| Openwrite | 即时渲染编辑器、专注模式、**选区操作**、批注、checkpoint 历史版本；创作助手携带选区/正文上下文 | 我们是纯 textarea；需加字数目标/光标上下文/历史回滚入口（后端 history 已有） |
| EmoArc（论文） | **情绪曲线可视化 + AI 改写耦合**：作者看着情绪轨迹改句子 | 已有情绪/节奏曲线后端（curve/emotion），需搬到编辑区旁实时展示 |
| 马良写作 | 大纲层级 + 节奏曲线 + 一致性校验的"编辑部"感 | 大纲/曲线/一致性后端已齐，前端要整合成"洞察面板" |

结论：**后端能力（点改/曲线/伏笔/思想脉络/历史）已经超过多数同行，差的是把能力"贴到作者手边"**——
选中即用、实时可见、可回滚。

## 2. 设计原则

1. **作者是主人，AI 是贴身手艺**：AI 只在你选中、你提问、你确认时动手；不抢键盘、不刷屏。
2. **选区即上下文**：选中哪里，AI 就懂哪里——浮动工具栏直接做润色/扩写/缩写/语气/节奏检查。
3. **实时但不打扰**：字数/目标、最近风格脉搏、节奏曲线常驻侧栏；红队/回译等重活只在交付时提示。
4. **一切可视化**：大纲（含卷级）、思想脉络、风格维度、节奏曲线都画出来，不藏在 JSON 里。
5. **可回滚**：每一次 AI 改动都可接受/放弃；历史版本可一键回退（后端已有）。

## 3. 信息架构（三栏伴随工作台）

```
┌ 左侧导航 ┐ ┌ 主区（当前视图） ┐ ┌ 右侧伴随面板（常驻） ┐
│ 项目列表  │ │ 会话聊天          │ │ ① 实时大纲（可编辑）   │
│ 作品库    │ │ 大纲编辑          │ │ ② 写作手写区（选区AI） │
│ 风格肖像  │ │ 成稿/审计         │ │ ③ 上下文（理解/素材/   │
│ 知识库    │ │ 风格/知识可视化   │ │    思想脉络/风格进度） │
└──────────┘ └───────────────────┘ └────────────────────────┘
```

主区 = 对话主导（澄清/大纲/写作由导演推进）；右侧伴随面板 = 实时状态与手写区。
写作阶段主区展示成稿，右侧手写区可编辑并触发选区 AI。

## 4. 交互模式清单

### P0（本轮实施）
- **选区 AI 工具栏**：在手写区选中文字 → 浮动出现 润色 / 扩写 / 缩写 / 更口语 / 更克制 / 节奏检查；
  执行后写回草稿并刷新洞察（复用 point-edit，改动即进风格档案）。
- **实时洞察卡（手写区顶部）**：字数/目标进度条 + 最近风格脉搏 + 节奏迷你曲线（/api/curve）+ 各节状态。
- **思想脉络可视化（上下文面板）**：展示"AI 理解到的你的主张/前提/推理/来源"，随对话实时更新。
- **风格进度条**：write/read 维度已学/总数 + Top 维度条。

## 5. 验收标准（P0）

- 手写区选中文字出现浮动工具栏，6 个动作都能执行并写回、风格档案吸收；
- 洞察卡实时反映字数/脉搏/节奏，刷新后不丢；
- 上下文面板能看到思想脉络与风格进度条；
- web 7 套 QA + agent 14 套全绿，final-qa 前端接线检查通过。
