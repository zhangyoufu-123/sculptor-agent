# STYLOTRACE 全面升级方案（Phase 1 已完成 · 待推进 Phase 2/3）

> **状态更新（v0.68）**：Phase 1 已全部落地并合入（命名校准 A1、RSA 形式化 A2、学习曲线 A3、
> 论文重排 A5、个人回避库 B1、上下文窗口编辑对 B2、可解释层 B7、embedding 合并 C1、doctor C4、
> 盲评统计 D1）。核心命名已按用户要求定为 **改迹调制（revision-trace modulation）**，不再使用
> "ACCM" 等生硬缩写；调制器已到 **十二维**（含 avoidance 第 12 维）。以下清单中 A1 的旧命名与
> 旧维度计数为历史记录，实际以 CHANGELOG / HANDOVER-v0.68 为准。

> 原则：不追"解码器顶会"，把创新主线做实为
> **修订监督适应（Revision-Supervised Adaptation）+ 可解释调制 + 姿态层诊断**。
> 所有升级必须保持"23 套 agent 测试 + 11 套 web 测试全绿"的回归底线；
> 重写只发生在有明确理由、且行为契约不变的模块。

## 0. 现状基线（v0.67）

- 核心：四层风格签名 → 个人 n-gram → 外层调制器（十一维特征 + 偏好对权重学习 +
  增量在线更新 + embedding 原型 + L3 作者清单 + 姿态层 posture）；
- 写作：`write.js → decodeSection`（候选级生成 n 候选 → 评分 → 选优）；
- 交互：澄清协议 + 外溢优先 + 作者写作清单 + 修改监督（edits.jsonl）；
- 质量：姿态层六层细读（LLM）+ 反 AI 审计 + 学术规范审计 + 全流程互操作；
- 工程：CLI + MCP + Web（零依赖 Node + 原生前端）、23+11 套测试、技能三安装点；
- 已知问题（升级要解决的）：
  1. 论文"统一 Token 对比解码"名不副实（候选级，非逐 token）；
  2. 作者识别 81.7% < TF-IDF 基线 82.2%（不能当主成绩）；
  3. 无第三方盲评、无显著性检验；
  4. `style-vector.js` 与 `embedding.js` embedding 实现重复；
  5. `decodeSection` 评分与解释耦合，无法支撑可解释层与状态向量；
  6. 编辑对训练未用上下文窗口、未按意图分流——"修改即标注"尚未做到位；
  7. director.js 1200+ 行，决策不可追溯。

## 4. 风险与取舍

1. **范围失控**是最大风险：Phase 1 是承诺线，Phase 2/3 按需推进；
2. **C2 重写回归风险**：必须保持 23+11 套全绿，否则回退；
3. **B6 依赖外部 API**：先探测，不支持就文档化降级，不硬做；
4. **B4 数据依赖**：状态向量需要 outline/curve 结构稳定，先确认再动；
5. **D1 盲评需要真人**：工具与报告我们备好，样本只能你组织收集；
6. **诚实底线**：论文所有新意表述都保留"据我们所知"式的限定，不写"首创/空白"。
