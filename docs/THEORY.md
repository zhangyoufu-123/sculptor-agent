# SCULPTOR 理论架构：为什么它在文字写作系统里是"另一个物种"

> 版本：v0.49 · 2026-08-11
> 用途：论文答辩 / 参赛评审 / 产品叙事。
> 原则：每一句"领先"都有对应实现与证据；不写无法辩护的话。

---

## 0. 一句话总纲

现有写作系统在做同一件事：**让机器写得好**。SCULPTOR 做的是另一件事：**让机器成为你**。

前者是生成问题，用更好的提示词、更大的模型、更多的模板就能逼近；后者是"作者建模"问题——
系统必须持续回答四个问题：**这个人是谁（风格）、他读过什么（知识）、他想说什么（意图）、
他亲手改过什么（偏好）**。这四问把写作从"文本生成"升级为"个体表征 + 个性化生成 + 人机协作"
的闭环，是范式级的差异，不是参数级的差异。

## 1. Agent 维度：从"聊天机器人"到"写作导演"

### 1.1 导演状态机（自主决策）

**理论**：写作不是一次生成，而是一个"规划→转译→复阅"（Flower & Hayes, 1981）的认知过程。
把流程交给用户逐句指挥，等于让外行指挥专家；把流程交给提示词模板，等于让专家背剧本。
SCULPTOR 选择第三种：**导演（Director）自主决策**——收到用户消息后自己决定下一步
（该问就问、该出大纲就出、该写就逐节写、该审计就审计、该请读者群像就群像），
只在真正的决策点（主题/立场/素材/立意/大纲确认/风格方向）停下等用户。

**实现**：`director.js` 的有限状态机（clarify→outline→write→revise→redteam→quality→
audience→deliver，含 restyle/rewrite_gaps 回环）；每一步写盘 `protocol/state.json`，
状态机唯一事实源；每阶段边界强制重读，杜绝"旧快照覆盖新状态"类 bug（曾真实修复）。

### 1.2 多 Agent 协作协议（生态位 / 供给 / 退让）

**理论**：通用 Agent 环境的难题是"抢话"与"边缘化"的两难。SCULPTOR 用一条主权顺序
（**用户指令 > 宿主当前动作 > Sculptor**）和一条生态位规则（**写作生态位内主导、
生态位外完全让位**）化解：主动感知（Observer/probe 确定性词表）、只提议一次、
被拒即退让；数据获取走"去重排队 → 宿主/学术/数据分析 agent 检索 → 回灌 →
缺口节自动重写"的供给闭环，Sculptor 决定要什么、何时要、怎么用。

**实现**：`observer.js`（probe 生态位判定）、`rag.js`（requests.jsonl 队列 + ingest 回灌 +
rewrite_gaps ≤2 轮）、`mcp.js`（被动工具协议）、写前重读校验与 hash 检测（`point-edit.js`/
`write.js` 的退让协议）。与 Codex / Claude Code / OpenCode 实测共存不冲突。

### 1.3 双形态交付（同一核心）

**理论**：能力必须长在用户所在的地方——CLI/MCP 给会用 Agent 的人，Web 工作台给不会的人。
同一导演状态机，两种皮肤，保证"产品形态不稀释核心能力"。

**实现**：`agent/bin/sculptor.js`（CLI）+ `mcp.js`（stdio JSON-RPC）+ `web/server.mjs`
（REST 包装同一 `agentStep`）；15+7 套 QA 双端同源验证。

## 2. 人工智能维度：三个"只有我们做"的机制

### 2.1 风格 = 个体对"完美表达"的结构化偏离（核心理论）

**理论**：设通用模型生成分布为 P，个体作者分布为 P_a。风格不是"某类文本的平均值"，
而是**偏离**：S_a = P_a − P 在可计算特征空间上的投影。AI 腔的本质是模型只会输出
P 的众数（平滑、无风险、平均脸）；写作助手要做的不是"更平滑"，而是**学出偏离方向
并把生成拉向那个方向**。风格由此从"提示词里的形容词"变成**可测量、可注入、可演进**的向量。

**实现（四层表征）**：
- L1 连续向量：作者语料 vs 基线语料的字符二元组方向差，EMA 增量更新（`style-vector.js`；
  呼应 ACL 2025 StyleVector 的"激活空间风格向量"思想，可升级真实 embedding）；
- L2 动态维度：14+7 维语言/结构轴 + 意象/偏好/素材子维，随写作演化、限量注入；
- L3 语言新鲜度（不可预测性）：度量"这句话像是人临时想出来的，还是模型顺着套路滑出来的"
  ——少见词语组合占比、低套话密度、句长错落度越高，文本越"新鲜"、越难预测
  （信息论意义下的高熵），AI 平滑文本则相反；这是"人味"的客观代理；
- L4 亲手修改记录：`(原文, 改后, 修改意图)` 三元组——用户每次亲手改过的句子
  是最高权重的风格证据（`edits.jsonl`），因为"他想要什么"永远比"他随口说什么"更真实。

配套两条纪律：**双风格分离**（"人想写的" write-style 与"人想听的" read-style 两个分布——
写作者要克制留白，读者需要一处光的余味）；**修改即风格教学**（选区点改/候选改写全部
吸收进档案与向量，让用户亲手改过的句子成为最强风格信号）。

### 2.2 思想脉络：把对话当"半条推理链"来接（对澄清的重新定义）

**理论**：模板式澄清在收集"填空题答案"；好的澄清在**接住用户的推理**。用户说
"我看过《乡土中国·文字下乡》，语言简化是文化发展的结果，可以顺着推理"——这不是一条
素材，是**半条推理链**：主张（烂梗有根源）、前提（某本书的论述）、推理方向（简化→
切断共同意义）都有了，只差系统把它显影出来并请用户确认。AI 只知道 1+1，用户知道
为什么 1+1；思想脉络让系统把"为什么"问出来。

**实现**：`thinking.js` 追踪"主张-前提-推理-理论来源"，LLM 做一步概括（"你的意思是：
烂梗不是没素质，而是简化走到极端后切断了共同意义——对吗？"），确定性只做信号识别；
`QUESTIONER_PROMPT` 规则 10/10.5-10.7 规定"思想层优先、先思想后信息最后规划、
蓝图状态只是清单、问什么由 LLM 自主判断"；RAG 知识背景（知识库/阅读记录检索）注入
提问；v0.49 新增**确定性收尾护栏**（蓝图字段全齐后 LLM 仍追问 ≥2 轮 → 强制放行），
保证真实模型不守 stop 规则也不会死循环。

### 2.3 三重保真与"读者在场"

**理论**：个性化不能以牺牲正确为代价。SCULPTOR 用三层防线把"像人"和"不丢内容"同时钉死：
反 AI 审计（确定性检测 + 按风格修订）、回译校验（中译英→回译→信息点核对，抓丢失/漂移）、
原创性与事实分级。并在交付前请 8 位"第一读者"群像反馈、交锋收敛出共识/争议/优先级——
把"读者感受"从玄学变成可执行的反馈流。

**实现**：`redteam.js`（黑名单/重复比喻/句式 + LLM 修订 ≤3 轮）、`roundtrip.js`、
`originality.js`、`fact-check.js`、`reader-gallery.js`（audience + debate）。

## 3. 数学维度：每个"感觉"都有可检验的度量

### 3.1 风格空间与作者轨迹

**理论**：把风格表示为向量空间中的点，每次写作/修改就是一次增量更新
（EMA：v_new = α·v_old + (1−α)·Δ），于是作者风格成为一条**随时间演进的轨迹**，
而不是一次性快照；压缩/续写/换设备都不丢。这与 StyleVector 的"训练免费、推理时干预"
在数学上同族，但我们在特征层（可解释的稀疏向量）而非激活层落地，零依赖、可审计。

### 3.2 人类化指标（"像人"的检验统计量）

句长标准差（节奏错落）、段落变异系数（结构呼吸）、句首去重率（句法多样性）、
词汇二元 TTR（词汇丰富度）——四量纲共同构成"真人写作区间"的判据。真实任务实测：
**句长标准差 14.4、段落变异系数 0.45、句首去重率 81%、TTR 0.78**，全部落在区间内。

### 3.3 对照与消融（可复现的实证协议）

- 同题三套风格对照：仅切换风格方向，成稿句长σ 3.7/8.3/5.0、字数 742/874/984、TTR 0.44/0.53/0.52
  ——**风格注入真实改变写法**（`experiment.js` + `web/test/final-qa.mjs`）；
- 消融实验脚本：逐模块关闭（风格/向量/少样本/读者群像），量化各自贡献；
- 盲评问卷 + 二项检验：`experiment blind` 生成可分发的问卷，`summarize` 给出选择率与显著性。

### 3.4 状态机与不变量

导演状态机是**确定性有限状态机**：每个阶段定义输入不变量（如"素材不足禁止生成大纲"）、
输出契约（每步写盘 + 进度消息）；子函数写盘后调用方强制重读——用工程不变量替代
"靠模型自觉"，这是数学意义上的可靠性保证。

### 3.5 风格向量可视化（可检验的"差别明显"）

用 8 维可解释风格特征（节奏均值/句长波动/短句占比/口语度/意象密度/情绪浓度/词汇丰富度/
语言新鲜度）对三类文本做归一化向量，并画成雷达图与欧氏距离矩阵（`scripts/style-visual.py`，
样本：SCULPTOR 作者实测文本、人类名家史铁生《我与地坛》、ChatGPT 典型 AI 腔文本）：

![风格向量对比：SCULPTOR 作者 vs 人类名家 vs ChatGPT](competition/style-vector-compare.png)

实测欧氏距离：**SCULPTOR 作者 ↔ 人类名家 1.48，SCULPTOR 作者 ↔ ChatGPT 2.02，
人类名家 ↔ ChatGPT 2.05**——两个"人类作者"彼此更近，且都与 ChatGPT 拉开明显距离。
这组可视化直观回答了一个评审必问的问题：**你的风格系统和"人"到底有多近、和"AI 腔"
到底有多远**——答案是：近到同侧，远到一眼可辨。

## 4. 工程维度：把"领先"变成"别人抄不走"

### 4.1 零依赖 + 唯一事实源

Agent 端零第三方依赖（Node 内置即可跑）；`protocol/state.json` 是唯一事实，
vault/ 沉淀全部风格/知识/大纲/曲线/伏笔；工作区隔离保证与任何宿主 Agent 零冲突。

### 4.2 可复现的质量体系

agent 16 套 + web 7 套自动化 QA，覆盖：一次一问与低意愿逃生、实时大纲、字数达标、
红队 8 文体×6 对抗输入、十种用户说法、风格差异对照、12000 字长文端到端、回译、
全格式导出；密钥扫描与引擎一致性进 CI。测试不是附属品，是产品的一部分——
15+7 套 QA 本身就是论文里的"工程产出"。

### 4.3 把能力贴到作者手边（Web 工作台）

选区 AI 工具栏、3 候选改写卡、版本回滚、专注/并排模式、实时洞察（字数/脉搏/节奏曲线）、
大纲图谱（卷→节卡片连线、点击定位草稿）、伏笔回收时间线、作品指标对比——
交互全部对应 Sudowrite/NovelCrafter/Openwrite 的最强项，且共享同一后端能力。

### 4.4 安全与退让

只写自己的工作区与用户指定文件；写前重读校验、外部改动即让位；凭据自动发现且脱敏；
密钥扫描进 CI。工程上"不打架"与"不泄露"是参与多 Agent 生态的入场券。

## 5. 与竞品的"绝对优势"论证（可答辩版）

| 维度 | 行业普遍做法 | SCULPTOR | 优势性质 |
| --- | --- | --- | --- |
| 风格 | 提示词"模仿余华" / 设定角色卡 | 四层向量 + 双风格 + 修改即教学，可测量可演进 | 范式级：从形容词到向量 |
| 澄清 | 收集填空题 / 固定清单 | 思想脉络接推理链 + 提问主次 + LLM 自主 + RAG | 范式级：从收集到理解 |
| 流程 | 用户逐句指挥 / 模板脚本 | 导演状态机自主决策，只在真决策点停 | 架构级：从工具到协作者 |
| 质量 | 无 / 单次检查 | 红队 + 回译 + 原创 + 事实 + 读者群像五重门 | 架构级：从单点到闭环 |
| 一致性 | 脑内记账 | 伏笔记账 + 跨章回收 + 文章圣经 | 能力级 |
| 交付 | 单一形态 | CLI + MCP + Web 双端同源，多模态进出、全格式导出 | 能力级 |
| 可复现 | 演示即全部 | 16+7 套 QA + 对照/消融/盲评协议 | 信任级 |

**一句话**：Sudowrite 管作品，NovelCrafter 管设定，通用模型管"写得好"；
**SCULPTOR 是唯一同时把"作者是谁"建出来、把作者的思想接住、把读者请到现场、
把这一切变成可复现工程的写作系统**——它服务的不是写作这个动作，而是写作者这个人。

## 6. 人文科学时代的价值（论文的"为什么"）

当机器把"表达"变成流水线，真正稀缺的不是"写得快"，而是"**这是我的话**"。
SCULPTOR 的立场是：**写作者不必迁就机器，机器应该学习成为他**。
它是人文科学时代的帮助产品——为不会组织语言的学生、被模板束缚的写作者、
每一个想在 AI 时代守住自己声音的普通人，提供一位懂他、学他、陪他的写作伙伴。
技术让机器更聪明只是前半场；**让每一个普通人被认真对待，才是后半场**。
