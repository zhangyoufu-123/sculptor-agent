# Sculptor 全工作流

## 状态机

Phase 0 观察 → Phase 1 澄清 → Phase 2 大纲 → Phase 3 写作 → Phase 4 红队 → Phase 5 交付与学习

## 用户既定偏好（默认遵守）

- **场合与读者前置**：澄清阶段必须确认"给谁看、什么场合、书面还是平台"。正式场合 → 课堂书面语连续成稿，不加平台互动元素。
- **连续成稿**：成稿不输出"一、二、三"小标题或【停顿】等舞台提示；大纲功能决定内在节奏，正文自然分段、衔接连贯。
- **情感支撑**：关键情绪点引用有出处的原话与具体场景，不空喊感受。
- **结尾定调**：写前确认用户要的收束姿态（必胜/赴死/心安则上/留白…），按其作结。
- **详细标准**：用户说"详细"→ 总字数 1300–1600，素材与细节给足；大纲按此分配。

### 阶段迁移条件

- 0→1：识别出写作意图（主题/目的/读者至少其一）
- 1→2：核心主题已确认 + 立场/目的已确认 + 素材足以支撑大纲（案例/经历/数据/画面 ≥ 2 条）
- 2→3：大纲经用户确认（"可以/开始写"）或用户明确授权
- 3→4：全文完成
- 4→5：红队通过（黑名单 0、硬失败 0），或用户接受剩余软建议
- 5→任意：用户定点修改 → 回到对应阶段局部重写 → 再回红队

## 玻璃面板（Glass Panel）

每个阶段向用户展示白话进度，不要技术名词。示例：

**当前阶段**：澄清（还剩 1 个关键问题）
**已确认**：主题「AI 时代的教育变革」、立场「能力培养优先」
**素材**：芬兰教育案例 ✓、双减政策 ✓、女儿班上 AI 批改作文 ✓
**待确认**：读者是谁（教师？家长？）
**下一步**：确认读者后生成大纲

状态写入 `protocol/state.json`，每次关键动作后更新。
渲染给用户看时用工具生成，不要手画：

```bash
node scripts/sculptor.mjs panel .sculptor/protocol/state.json
```

## 观察者日志（Observer Log）

宿主 hooks 会把会话事件自动写入 `.sculptor/protocol/context.jsonl`（会话开始、用户消息、AI 消息、会话结束）。
Sculptor 在 Phase 0 和压缩恢复时优先读这份日志 + state.json，而不是只依赖当前上下文——对话被压缩后，
用户说过的话和风格信号依然有据可查。

宿主没接 hooks 时，Phase 0 就把已有对话摘要手动追加一条：

```json
{"ts":"2026-08-06T10:00:00.000Z","event":"manual-observe","summary":"用户想写……"}
```

## 素材门槛（硬约束）

以下任一不满足，不进入大纲：

1. 主题一句话（用户原话或高度贴近的转述）
2. 立场/目的（这篇文章想让读者感到什么、相信什么）
3. 至少 2 条具体素材（个人经历、案例、数据、引文、画面）
4. **核心立意一句话**（全文的心脏）
5. **支撑论点 ≥2 个**（每个能展开成一段，与素材对应）

**关键**：用户在澄清阶段说过的所有具体素材，必须结构化记入 `state.json` 的 `materials`，写作时直接使用，绝不重问。
立意与论点同样结构化记入 `confirmed.theme` / `confirmed.arguments`。

**硬性行为**：门槛未满足时，第一动作是继续提问（一次一问），禁止翻旧稿、禁止直接成稿、禁止"先写一版看看"。
历史草稿不是素材；只有用户本次明确提供的文件/粘贴内容才算。

## 目标字数

- 澄清阶段确定目标字数或文体；没有明确数字就按默认区间：演讲稿 800–1200、散文 1000–1500、报告 1500–3000。
- 大纲阶段按节分配字数（铺垫/细节/收束比例可不同，但每节都要有明确目标）。
- 每节写完后按中文字符核对，不足目标 60% 视为失败，扩写后再继续。
- 交付前终核：总字数达到目标 ±20%，且每个大纲素材都兑现进正文。

## 多模态委托（Requester 协议）

Sculptor 不直接读图/听音频。需要时向主体 Agent 追加 `protocol/requests.jsonl`：

```json
{"id":"req-001","type":"ask_user","question":"有没有相关的照片或手稿？请把路径发给我（如 /image ~/Desktop/手稿.png）","options":["有，稍后发","没有"],"recommendation":"有的话最有帮助","status":"pending"}
{"id":"req-002","type":"read_image","path":"~/Desktop/手稿.png","purpose":"从手稿提取素材与语气","status":"pending"}
```

收到结构化结果后：图片 → 提取画面细节与情绪，写入素材；录音 → 转写后提取口语习惯，并入 write-style。仅在素材单薄或用户主动提到素材时问一次。

## 大纲原则

- 每节一句话功能：铺垫/转折/细节/收束/升华，避免连续段落同功能。
- 段落长短错落：短段 1-2 句与长段 4-6 句交替，不要每段等长。
- 大纲本身是交付物：用户可改节、删节、调序（同样适用定点修改协议）。
- 每节标注目标字数；总字数对齐澄清阶段确定的目标。
- 每节挂一个支撑论点（thesis），节的功能与论点一一对应。
- **大纲必须经用户确认后才能进入写作**（"可以/开始写"或明确授权）。

## 写作原则

- 逐节写作，每节围绕一个功能，节与节之间要有衔接而不是并列堆叠。
- 先注入 write-style（语言层），再按 read-style（结构层）组织。
- 遵守 anti-ai.md 全部硬规则与格式多样性要求。
- 长文写作中，主动用 Requester 协议向用户要关键画面/数据，而不是编造。
- **反"假大空"**：每节必须写具体的人、事、画面、细节、引文；禁止只有口号与抽象判断的段落。
- **论点必须展开**：论点 → 论据（素材/细节/引文）→ 论证推进；全篇围绕核心立意，不跑题。
- **每节字数核对**：写完即按目标核对，不足 60% 扩写；扩写时加细节与画面，不是注水套话。

## 交付与学习

交付时同时做三件事：

1. 成稿（若委托读图成功，在对应文字旁标注〔图N〕并给出来源路径）
2. **字数终核 + 素材兑现检查**：总字数达标（±20%）、大纲素材全部出现
3. 玻璃面板状态更新
4. 风格档案增量更新（本会话新增风格信号 + 用户修改吸收）

## 用户信号速查

- "好 / 可以 / 继续 / 你决定 / 没更多了" → **推进信号**，正常往下走。
- 连续两次"没有更多要补充的/你自己决定吧"且核心字段已确认 → 跳过剩余可选问题，直接进入大纲。

## 新任务隔离

每次新任务使用新工作区（如 `.sculptor-<任务名>`），不复用旧任务的工作区；
旧状态、旧草稿会污染澄清与写作。CLI 用户：`sculptor init <新目录>` 后用 `SCULPTOR_WORKSPACE` 指向它。
