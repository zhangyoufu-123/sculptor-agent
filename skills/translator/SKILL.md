# Stylotrace 翻译官

翻译的本质是把同一件事用两种语言说清楚。本 skill 用回译校验做两件事：**内容保真**（信息点是否在翻译中丢失/漂移）和**风格对比**（翻译前后语言节奏、密度、套话是否变化）。按需启动，用户要求时才运行。

## 触发条件

用户在以下情况主动提出时启动：

- 翻译一段文字（含"帮我翻译成英文"）
- 回译校验（"翻译后检查信息有没有丢"）
- 拿翻译做校对（"把这段翻成英文再翻回来看看"）
- 翻译前后风格对比（"翻译后风格会不会变"）

不触发：普通写作、改写、润色（那些走 sculptor skill）。

## 运行

优先用完整引擎（带风格向量与深度指标），不可用时用独立脚本：

```bash
# 独立脚本（零依赖，Node >=18，随 skill 安装）
node scripts/roundtrip.mjs --file 文章.md
node scripts/roundtrip.mjs "直接给文本"
node scripts/roundtrip.mjs --json "文本"      # 机器可读
node scripts/roundtrip.mjs --metrics-only "文本"  # 离线，只算风格指标

# 完整引擎（若已安装 sculptor）
sculptor roundtrip --file 文章.md
```

LLM 配置走环境变量 `SCULPTOR_LLM_API_KEY / SCULPTOR_LLM_BASE_URL / SCULPTOR_LLM_MODEL`（无则回退 `OPENAI_API_KEY`）；未配置时自动降级为"仅风格指标"离线模式，不中断。

## 工作流（脚本已内置，按需解释给用户）

1. **内容分析**：从原文提取必须保留的信息点（专名/数字/论断/关键意象）
2. **中译英**：直译，不润色、不增删
3. **英译中**：忠实回译
4. **信息点核对**：回译里逐点核对"保留/丢失/漂移"（LLM 判定，失败走确定性核对）
5. **风格对比**：原文 vs 回译文（同为中文）的句长标准差、句首去重率、词汇 TTR、AI 套话数

## 交付格式

给用户一份简短报告（脚本已渲染），重点讲三件事：

- 信息有没有丢：列出丢失/漂移的信息点，建议回填到原稿；
- 风格有没有变：指出变化明显的指标（节奏、密度、套话），说明这是翻译损耗还是真问题；
- 结论：`pass`（信息完整）或 `attention`（需要修订）。

不要在报告里堆技术术语；用"这句话在回译里消失了""句子的长短变化变大了"这类人能懂的话。

## 注意

- 只做校验和报告，**不擅自改用户的稿子**；用户要改，走 sculptor 的定点修改。
- 翻译损耗（成语、双关、意境的丢失）≠ 用户原文的问题，报告里要区分"翻译造成的"和"原文本来就模糊的"。
- 长文按段落分批跑，单批不超过 3000 字，避免超上下文。
